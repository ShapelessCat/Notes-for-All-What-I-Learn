*** DONE What's Different About TypeScript? - 3
CLOSED: [2026-10-04 Sun 00:46]
*Types makes TypeScript different from JavaScript.*

- _Common *MISCONCEPTION*:_
  TypeScript's core mission is to make JavaScript a /strongly typed language/,
  like C# or Rust

  1. TypeScript wasn't invented to make JavaScript strongly typed.

  2. TypeScript was built to allow amazing tooling for JavaScript.
     * TypeScript aims to provide just *enough strong typing* to make working
       with JavaScript more pleasant and productive.
       + *enough strong typing*:
         *enough* for implementing powerful IDE features like _autocomplete_,
         _inline errors_, and _automatic refactors_.

*** DONE A High-Level View of How TypeScript Works - 4
CLOSED: [2026-10-04 Sun 22:23]
- A JavaScript-only project (illustrated in Figure 1-1):
  1. Write code in files with .js extensions.
  2. Those files are able to be directly executed in the browser or a runtime
     environment like Node.js.

- A TypeScript project (illustrated in Figure 1-2):
  1. Write code is primarily in .ts or .tsx files.
  2. Unlike .js files, .ts files *can't usually be executed directly by the
     browser or a runtime.*
     * TypeScript's _tsc_ CLI transforms your .ts files into .js files, which
       means you are able to
       1) take advantage of TypeScript's features while writing your code,
       2) BUT the output is still plain JavaScript.

**** Manual Autocomplete - 10
You'll often want to _trigger autocomplete MANUALLY_. In VS Code, the
*ctrl-spacebar* keyboard shortcut will list suggestions for what you're typing.

For example, if you were _adding an event listener to an element,_ you would see
a list of available events:
#+begin_src typescript
  document.addEventListener(
      "", // Autocomplete here
  )
#+end_src

Pressing *ctrl-spacebar* with the cursor inside the quotation marks will show a
list of events that can be listened for:
#+begin_src text
  DOMContentLoaded
  abort
  animationcancel
  ...
#+end_src

If you want to *narrow down* the list to the events you were interested in,
_enter =drag= before pressing ctrl-spacebar;_ only the appropriate events will
display:
#+begin_src text
  drag
  dragend
  dragenter
  dragleave
  ...
#+end_src

*** DONE JSDoc Comments - 16
CLOSED: [2026-10-07 Wed 22:00]

- JSDoc is a syntax for adding documentation to the types and functions in your
  code.
  * *It allows VS Code to show additional information in the pop-up that appears
    when hovering.*

  * *This feature is extremely useful when working with a team.*

- Here's an example of how a ~logValues~ function could be documented:
  #+begin_src typescript
    /**
     ,* Logs the values of an object to the console.
     ,*
     ,* @param obj - The object to log.
     ,*
     ,* @example
     ,* ```ts
     ,* logValues({ a: 1, b: 2 });
     ,* // Output:
     ,* // a: 1
     ,* // b: 2
     ,* ```
     ,*/

    const logValues = (obj: any) => {
        for (const key in obj) {
            console.log(`${key}: ${obj[key]}`);
        }
    };
  #+end_src

  - The ~@param~ tag is used to describe the parameters of the function.
    The ~@example~ tag is used to provide an example of how the function can be
    used, *using markdown syntax.*

  - Many tags are available for use in JSDoc comments.
